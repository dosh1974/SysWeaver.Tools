# SwWeb

[⬆ SysWeaver.Tools overview](../README.md)

> Build, lint and migration tool for the SysWeaver web front end (`srcWeb` folders): builds the `sw/*.js` / `sw/*.css` bundles from `sw/bundles.json`, checks web sources against the server contract (translation, template, build and serving rules) and migrates old format pages to the new `Sw` format.

| | |
|---|---|
| **Layer** | Tool (command line) |
| **Kind** | Command line tool |

## Purpose

The SysWeaver front end is written as many small classic scripts (`core/*.js`, `ui/*.js`, `ui/*.css`) that are served as a few bundles (`sw/core.js`, `sw/ui.js`, `sw/ui.css`, ...). The server build only compresses files, so the bundles are generated by this tool and committed like any other source.  
The server also imposes rules that are easy to break and hard to notice (the translation rewriter matches `_T(` anywhere, `a.b.js` is served as `a/b.js`, `${Session.X}` inside a JS template literal is replaced by the template engine, `.mjs` files are not embedded, ...), and pages must be classic scripts that load nothing from the internet. `SwWeb check` finds those.

## How it fits into SysWeaver

A stand-alone developer tool, not called by any build. Run `SwWeb bundle <srcWebRoot>` after editing a bundled source file and `SwWeb bundle <srcWebRoot> --check` / `SwWeb check <srcWeb>` in CI or before committing. `SwWeb migrate <folder>` moves old format pages (including other projects' pages) to the new format. It has no dependencies (not even SysWeaver.Common).

**Porting an app** to the new front end and to Design v2: follow the porting guide [`SysWeaver.HttpServer/srcWeb/PORTING.md`](https://github.com/dosh1974/SysWeaver/blob/main/SysWeaver.HttpServer/srcWeb/PORTING.md) (every rule with before / after, and whether `migrate` does it or `check` flags it). The short version:

```
SwWeb migrate <srcWeb> --dry-run --level design --report port.md   # what is automatic, what is manual
SwWeb migrate <srcWeb> --backup <dir>                                # do the automatic part (includes, API, tokens)
SwWeb migrate <srcWeb> --level design                                # + the Design v2 rewrites; the report lists the manual follow-ups
SwWeb check <srcWeb> --strict --design                               # until 0 findings
```

## Using it

**Getting the tool**: SwWeb is a plain .NET console app without dependencies. Build it from this repository (.NET 10 SDK) and run the exe, or use `dotnet run`:

```
git clone https://github.com/dosh1974/SysWeaver.Tools
dotnet build SysWeaver.Tools/SwWeb -c Release        # -> SwWeb/bin/Release/net10.0/SwWeb.exe (SwWeb.dll + legacy_globals.txt next to it)
dotnet run --project SysWeaver.Tools/SwWeb -c Release -- check D:\MyApp\srcWeb --strict --design
dotnet test SysWeaver.Tools/SwWeb.Tests              # the tests
```

Copy the whole output folder if you want it elsewhere (the mapping table is embedded; `legacy_globals.txt` next to the exe overrides the embedded copy).

```
SwWeb bundle <srcWebRoot> [--check] [--manifest <path>]
SwWeb check <folder> [--strict] [--design] [--skip <pattern>].. [--no-default-skip] [--template-var <name>]..
                     [--legacy <file>] [--full-paths] [--quiet]
SwWeb migrate <folder> [--dry-run] [--backup <dir>] [--report <file>] [--include <glob>].. [--exclude <glob>]..
                       [--level includes|api|design] [--map <file>] [--legacy <file>] [--keep-legacy] [--force-includes] [--no-jsdoc-header] [--quiet]
SwWeb upgrade <folder> [--dry-run] [--backup <dir>] [--report <file>] [--include <glob>].. [--exclude <glob>]..
                       [--level includes|api] [--map <file>] [--legacy <file>] [--keep-legacy] [--force-includes] [--quiet]
SwWeb mapping
SwWeb rules
SwWeb icons <folder>
SwWeb contracts <folder> [--out <file>]
SwWeb tokens <folder>
SwWeb verify-build <folder> [--full-paths] [--quiet]
```

Options start with `--` (or `-`) and are case insensitive. `-?`, `-h`, `--help` show the usage.

### bundle

Builds every bundle of `<srcWebRoot>/sw/bundles.json` (or `--manifest <path>`; the paths in it are still relative to `<srcWebRoot>`).

- `--check`: writes nothing; exit code 3 if a bundle is missing or differs from what would be generated, or is over its size budget (`MaxKB`, `MaxGzipKB`). Both modes print each bundle's size.
- A bundle is only written when its content changes (the file time stamp of an up to date bundle is untouched).
- A missing source file is reported with its relative and full path, that bundle is not written (other bundles are) and the exit code is 4.
- **Source verification** (so a half edited file can't break every page): a `.js` bundle is not written, and the previous bundle stays in place, when a source doesn't lex or balance its brackets (the `syntax` rule of `check`), when the joined bundle doesn't, or when a source calls a bare name (`name(...)`, `new Name(...)`) that no JavaScript source of any bundle of the manifest declares (function, class, `var` / `let` / `const` incl. destructuring, parameters, catch bindings) and that is no browser / language global. Errors name the source and line: `ui/controls.js(1234,9): undefined: "endSave(...)" calls a name that no bundle source declares`; exit code 3. A name that another script defines (loaded by the pages) is known when a comment of the source names it (`/* global Edit, EditOptions */`, or a description such as "needs the edit/ scripts: Edit, EditOptions"); member calls (`window.x()`, `Sw.X()`) are not checked. `--no-verify` skips the verification. The bundle is written to `<out>.tmp` and moved over the old one.

#### bundles.json

```json
{
  "Bundles": [
    {
      "Out": "sw/core.js",
      "Header": "Optional text for the generated header comment",
      "Files": [ "core/base.js", "core/i18n.js" ]
    },
    {
      "Out": "sw/ui.css",
      "Files": [ "ui/ui.css" ]
    }
  ]
}
```

| Member | Meaning |
|---|---|
| `Out` | The output file, relative to the web root, `.js` or `.css`, a single dot in the file name. Each `Out` may only be used once |
| `Files` | The source files in concatenation order, relative to the web root (inside it), all with the extension of `Out`, no duplicates |
| `Header` | Optional text added to the header comment (may contain new lines) |
| `LoadOnce` | Optional, `.js` only: wrap every source in a load once guard, so a source that several bundles of one page contain runs once (ex: `sw/session.js` + `sw/core.js`, `sw/session.js` + `sw/theme.js` + `common/common.js`). A `.js` bundle that shares a source with a `LoadOnce` bundle must be `LoadOnce` too: it fails otherwise ("ui/base.js is also in common/common.js (LoadOnce): set "LoadOnce": true here too ..."; AS6-1). See "Load once" below |
| `MaxKB`, `MaxGzipKB` | Optional size budget of the output in KB (as written, and gzip compressed at the smallest size, about `gzip -9`). A bundle over its budget fails `bundle` and `bundle --check` (exit code 3; it is still generated): a small bundle (`sw/session.js`) can't grow back into the full core unnoticed. Raise it only when the growth is intended. `bundle` prints every bundle's size (`sw/session.js: up to date (10 files, 198.5 KB of 218, 49.3 KB gzip of 54)`) |

Comments (`//`, `/* */`) and trailing commas are allowed in the manifest. Member names are case sensitive.

#### Output format

- A JSDoc header comment: `@file <Out>: GENERATED by SwWeb bundle from sw/bundles.json, do not edit!`, the rebuild command, the optional `Header` text and the list of source files in order. (`*/` in names or header text is written as `* /`.)
- Per source file a separator comment, `// ---- core/base.js ----` (js) or `/* ---- ui/x.css ---- */` (css), then the file content.
- Encoding: **UTF-8 with a BOM** (the convention of the SysWeaver source files, Visual Studio's default). Sources may be UTF-8 with or without a BOM; BOMs at the start of a source are removed so the bundle has a single BOM at the start. A source that isn't valid UTF-8 is an error.
- Line endings: **CRLF** everywhere (sources with LF or CR are converted). Leading empty lines and trailing white space of each source are removed and every source ends with a new line.
- JavaScript separation: a `;` line is added after a source whose last token isn't `;`, or that ends with `}` while the next source starts with a token that would continue the expression (`(`, `[`, `` ` ``, `+`, `-`, `/`, ...). A source that ends inside a block comment or template literal is an error (it would swallow the next file). A CSS source that ends inside a comment is an error.
- Deterministic: the output only depends on the manifest name, the bundle definition and the source contents (no dates, no absolute paths).
- Note: a `"use strict"` directive at the top of the first source applies to the whole bundle (directives of later sources are plain expressions).
- **Load once** (`"LoadOnce": true`): every source is wrapped in
  `if (!((window.Sw = window.Sw || {}).Sources = window.Sw.Sources || {})["core/x.js"]) { window.Sw.Sources["core/x.js"] = "sw/out.js"; ... }`.
  `Sw.Sources` maps each source that ran to the bundle that ran it, so a page that loads `sw/session.js` and later `sw/core.js` runs the
  shared core files once (one BroadcastChannel, one session manager) and then only the files that `sw/core.js` adds. The header comment
  says so. A source of such a bundle must not declare `let`, `const` or `class` at its top level (they would become local to the guard
  block): the bundle is not written, and the error names the source and the declaration (wrap the file in an IIFE). A source whose only
  top level declarations are functions (`core/i18n.js`: the global translation markers `_T`, `_TF`, `_TH`, `_TFH`, which must stay plain
  global functions) is not wrapped (a comment line says so): declaring a function again is harmless, and the rest of such a file must
  guard itself (`if (Sw.I18n) return;`). `LoadOnce` on a `.css` bundle is an error.

### check

Recursively lints a folder (normally a `srcWeb` folder, the rules for templated files use paths relative to it). File and folder names are checked for all files; the content of `.js`, `.css`, `.html` / `.htm` and templated files is checked.

**A folder above the web roots** (a repository or solution folder such as `D:\SysWeaver.Services`): when the folder is neither a `srcWeb` / `srcData` folder nor inside one and has such folders below it, only those are checked (each as its own web root, paths printed relative to the given folder, ex: `FakeTextService/srcWeb/app/text.js(3,1): ...`). Build outputs next to them (`web/**`, `*.br`), the `*.Services.json` manifests and the project folder names (`SysWeaver.X`, which `folder-name-dot` would report) are not web files and are never looked at; `migrate` on such a folder also only touches the web roots.

| Option | Meaning |
|---|---|
| `--strict` | Also run the strict rules (legacy globals in new-format pages) and fail on warnings |
| `--design` | Also run the Design v2 porting rules (`design-*`, `a11y-*`, see the table below) and the [UX guide rules](#ux-guide-rules) (`ux-*`): warnings, so they only fail with `--strict` |
| `--framework` | Also run the UX guide rules on the framework's own files (`core/`, `ui/`, `shell/`, `common/`, `brand/`, `app/application.*`; never the generated `sw/` bundles), which the design rules skip |
| `--skip <pattern>` | Skip more paths (repeatable). `name/` = any folder with that name, `*.ext` / `name.js` = a file name, `a/**/b*.js` = a relative path (`*`, `?`, `**`; case insensitive) |
| `--no-default-skip` | Don't skip the default vendored paths |
| `--template-var <name>` | An extra known template variable, ex: a config `Variables` key (repeatable) |
| `--legacy <file>` | Use another legacy globals list |
| `--full-paths` | Print full paths instead of paths relative to `<folder>` |
| `--quiet` | Only print the summary |

Default skip list (vendored or generated, see `CheckOptions.DefaultSkip`): folders `external/`, `prettier/`, `ace/`, `node_modules/`, `.*/` (hidden, ex: `icons/.opt`), `bin/`, `obj/`; files `*.min.js`, `marked.js`, `md5.js`, `UZIP.js`, `chart.umd.js`, `chartjs-*.js`, `brand/fonts/*.ttf` (the brand font sources, served as data urls by `brand/fonts.css`), `*.br`, `*.gz` (compressed build outputs).

Output: one line per finding, sorted by path and position, then the number of findings per rule and a summary:

```
common/common.js(5361,59): tr-newline: the _T literal contains \n (minified to a backtick literal, not translated)
my-folder/: folder-name-dash: folder name "my-folder" contains '-' (embedded as 'my_folder', so its URLs change)
3d/: folder-name-digit: warning: folder name "3d" starts with a digit (embedded as '_3d')
```

Format: `path(line,col): rule: message` (1-based line and column, UTF-16 chars); names rules have no position (`path: rule: message`); warnings have a `warning: ` message prefix.

#### Rules

`SwWeb rules` lists them. Strict rules only run with `--strict`, design rules only with `--design`.

| Rule | Severity | Checks |
|---|---|---|
| `file-name-dots` | error | A file name with more than one dot (except `*.min.js`): `a.b.js` is served as `a/b.js` (not for the data files of a `srcData` folder: they are server side data loaded as resources, only its `.html` / `.js` / `.css` templates follow the url rules) |
| `folder-name-dash` | error | A `-` in a folder name (embedded as `_`, the URLs change) |
| `folder-name-digit` | warning | A folder name starting with a digit (embedded with a `_` prefix) |
| `folder-name-dot` | error | A `.` in a folder name, except a leading one (the resource name joins folders with dots, so `a.b/x.js` is served as `a/b/x.js`) |
| `mjs-file` | error | A `.mjs` file (not embedded; use classic scripts) |
| `encoding` | error | Not valid UTF-8 |
| `syntax` | error | Unterminated string, template, regex or comment (JS), unterminated tag / comment / raw text element (HTML), and unbalanced brackets in a script (`.js` files and inline scripts): `()`, `[]`, `{}` and template substitutions `${}` must pair up; only the first mismatch of a script is reported (with the position of the opening bracket). A token based check, not a parser: `1 +;` is not found |
| `tr-not-literal` | error | `_T`/`_TF`/`_TH`/`_TFH` called without a `'...'` or `"..."` first argument (backtick, variable, expression, no argument, or a comment between the name and `(`): not translated by the server. The runtime definitions `function _T(...)` are allowed |
| `tr-member-call` | error | `obj._T(...)` / `obj?._T(...)`: the server turns it into invalid JS |
| `tr-identifier-suffix` | error | A call of an identifier ending with `_T`, `_TF`, `_TH` or `_TFH` (ex: `MAX_T(`): the server rewrites it |
| `tr-in-text` | error | The pattern `_T(` (also `_TF`, `_TH`, `_TFH`, with optional spaces before `(`) in a JS string, template, regex or comment, in HTML text, comments or attributes (including `on*` handlers, which are not translated), in non-JS script elements or in CSS |
| `tr-newline` | error | A translated literal (first argument or quoted context argument) containing `\n`, `\r` or a line continuation: the minifier turns it into a backtick literal, so it is not translated |
| `tr-mixed-quotes` | error | A translated literal containing both `'` and `"` (same reason) |
| `tr-alias` | error | A translation function used as a value: `const t = _T`, `list.map(_T)`, `{ f: _T }` as a value: the server only translates direct calls with a literal, so the aliased texts are never translated (not: the definition `function _T`, `var _T =`, `typeof _T`, a member `x._T`) |
| `tr-untranslated` | warning | A user visible literal text in code without `_T`: a Sw option (`Title`, `Text`, `Description`, `Label`, `Placeholder`, `Tooltip`, `Hint`, `Content`, `Message`, `EmptyText`, `OkText`, `CancelText`, `AriaLabel`, `Html`; `text`, `title`, `placeholder`, `html`, `aria-label`, `alt`), the texts of `Sw.Toast` / `Sw.Info` / `Sw.Fail` / `Sw.Dialog.Alert` / `Confirm` / `Prompt` and `document.createTextNode`, `textContent` / `innerText` / `title` / `placeholder` / `ariaLabel` / `alt` assignments, `setAttribute("title" / "aria-label" / "placeholder" / "alt", ...)`, and the words between the tags of an html string (`innerHTML`, `outerHTML`, `insertAdjacentHTML`). A text is a literal with a word (not a lower case key, a class, a url, a file, css, a key combination like `Ctrl+C`). And a new-format page whose own scripts make texts (a literal with two words) but never call `_T` (the step "no translated text" of a framework-free page after the includes). The page's html text and its `title` / `placeholder` / `alt` attributes are translated by the server and not reported. Not checked: the generated bundles, `common/common.js`, `app/application.js`, `ui/compat*.js`, the brand hook `app/app.js`, files only loaded by `SwWeb:no-framework` pages. Exceptions: `SwWeb:no-tr (why)` on the line or the line before, `SwWeb:no-tr-file (why)` in the first 2000 characters of a developer-only file. `migrate --level design` wraps the plain ones |
| `theme-include` | warning | A page that links `sw/ui.css` (or `sw/shell.css`) without `common/theme.css` before it: the Sw tokens keep their light defaults, so the page stays light in Dark, Pro, Application and Hacker while the shell around it switches (also reported when the theme is linked after `sw/ui.css`). `migrate` adds it |
| `tr-format` | error | Arguments that don't match the placeholders (they break the page text at run time): `_TF` / `_TFH` with format arguments after the text and the optional context (they never format: the page shows `{0}`; once translated the server passes them to `_T` with the context as `{0}`), or `_T` / `_TH` whose highest placeholder `{n}` has no argument (a trailing quoted literal is the context, not an argument: `_T("{0} is {1}", a, "on")`). Warnings: `_T` with arguments but no placeholder, `_T` with a placeholder and no arguments at all (a format filled later is marked with `_TF`). A spread argument is not counted |
| `template-var` | error | `${` in a templated file (`index.html`, `debug.html`, `app/manifest.json`, `app/Home.html`, `common/theme.css`; case sensitive paths) that isn't a known template variable (`Color.*`, `Env.*`, `EnvInfo.*`, `Server.UTC`, `Request.Prefix/IP`, `Session.Lang/User/UserName/Email/Domain/NickName`, `TrN`, `VrN`, `--template-var` names) with optional case / encoding prefixes (`_^~` `@#%$£¤*!/`) |
| `template-css` | error | A template variable in templated CSS outside a `--custom-property` value (the minifier drops the `;` after it) |
| `template-literal-var` | error | `${Session.`, `${Env.`, `${EnvInfo.`, `${Color.`, `${Server.`, `${Request.` or `${TrN}` in a JS template literal (or in a JS string / comment of a non templated file): the server template engine replaces it |
| `jsdoc-header` | error | A `.js` file that doesn't start with a JSDoc file header `/** ... @file ... */` (a leading `"use strict";` is allowed). The brand hook `app/app.js` (also below a folder) is exempt: it is a deployment config file, see `_docs/WebBranding.md` |
| `debug-markers` | error | Unbalanced `//DEBUG_BEGIN` / `//DEBUG_END` lines (Compress removes the lines between them; a missing end removes the rest of the file) |
| `minifier-reorder` | error | A destructuring default value or computed key reads a name declared earlier in the same `var` / `let` / `const` declaration. Consecutive declarations of the same kind count as one, because the minifier merges them. The build's minifier (`Compress.exe` -> `minify.exe`, tdewolff minify v2.24.19) moves the first destructuring declarator whose *initializer* doesn't name an earlier declarator to the front, and it ignores the pattern itself. Example: `const s = t.length, { end: o = s - 1 } = i` (or the same as two statements) becomes `const{end:o=s-1}=i,s=t.length`. The release build then throws "Cannot access 's' before initialization" (with `var`, a silent `undefined`), while the unminified srcWeb works. Fix: compute the default after the destructuring (`const { end } = i; const o = end === undefined ? s - 1 : end;`), or put another statement (or a different declaration kind) between the two. Splitting into two adjacent statements of the same kind does **not** help. A deliberate case is marked with `SwWeb:allow minifier-reorder` on the line or the line before |
| `internal-id` | warning, strict | A comment, string or document (`.js`, `.css`, `.html`, `.md`, `.txt` of a web folder; not vendored libraries) names an internal change tracking id: a fix round id of the form `C<n>R<n>[-Name[-n]]` / `F<nn>-Name[-n]`, a tracker id `<area>-<letter><n>` of the families `B`, `CR`, `EX`, `ME`, `UM`, `CH`, `ED`, `AU`, `AC`, `SM` (`B-C5`, `B-L3`, `CR-S18`, `UM-S2`, also with a `BB-` prefix), `CR<n>-A<n>`, `RD-<n or Name>`, `BB-<n>`, `S2F-Name`; a number may have a letter suffix (`CR-S18a`). The framework sources (`core/`, `ui/`, `shell/`, `common/common.js`) are checked too, the generated bundles `sw/` not. Standard names (`UTF-8`, `SHA-256`, `ISO-8601`) are not ids. Readers of the framework cannot look these up: describe the rule or the reason itself |
| `external-resource` | error | An internet url (`http:`, `https:`, `ftp:`, `ws:`, `wss:` or protocol relative `//`) that a page loads statically: `<script src>`, `<link href>` with a loading `rel` (`stylesheet`, `icon`, `manifest`, `preload`, `modulepreload`, `prefetch`, `preconnect`, `dns-prefetch` ...), `<img src / srcset>`, `<iframe src>`, `<frame src>`, `<embed src>`, `<object data>`, `<video src / poster>`, `<audio src>`, `<source src / srcset>`, `<track src>`, `<input type="image" src>`, CSS `@import` / `url()` (in `.css` files and `<style>` elements, comments ignored) JS `import` specifiers and a literal url in either argument of `Sw.Net.IncludeJs` / `IncludeCss` (also the legacy `includeJs` / `includeCss`, ex: `Sw.Net.IncludeJs(null, "https://cdn.example.com/lib.js")` or `Sw.Net.IncludeCss("https://cdn.example.com/", "lib.css")`). Plain links (`<a href>`, `rel="canonical"`) and `data:` urls are not reported. A documented optional online feature is allowed with a `SwWeb:allow-online` comment on the line or the line before |
| `external-request` | error | A script requests a string literal internet url: `fetch("https://...")` (also `window.fetch`), `importScripts`, `new WebSocket / EventSource / Worker / SharedWorker / Request(...)`, `xhr.open("GET", "https://...")`, `navigator.sendBeacon`, `x.src = "https://..."` (also `srcset`, `poster`, `data`) and `x.setAttribute("src", "https://...")`. The start of the first literal counts (`"https://api.example.com/" + id` is reported); urls built from variables, `window.open(url)` and `a.href = ...` (links) are not. Allowed with a `SwWeb:allow-online` comment on the line or the line before (ex: the optional password leak check in `auth/Auth.js`) |
| `root-relative-url` | warning | The same places with an url starting with a single `/` (ex: `/sw/core.js`): it breaks when the server runs below a path (reverse proxy); use a relative url. Urls starting with a server template expression (`${@Base Url}sw/core.js`) are relative |
| `es-module` | error | ES module syntax: `<script type="module">` / `"importmap"`, `import` / `export` declarations, dynamic `import()` and `import.meta` in `.js` files and inline scripts. `x.import`, `{ import: 1 }` and methods named `import` / `export` are ignored |
| `css-import` | error | An `@import` in `app/app.css` (also below a folder: `.../app/app.css`): every page adopts the brand style sheet without its imports, so put everything in the one file |
| `brand-url` | error | A relative `url()` in a `--custom-property` of `app/app.css` not written as `../<folder>/<file>` (ex: `url(acme-mark.svg)`): a url in a variable is resolved against the style sheet that uses the variable (one folder below the root, ex: `sw/ui.css`), so write `../app/acme-mark.svg`. `data:`, `#id` and internet urls are left to the other rules |
| `font-file` | warning | A font file (`.woff`, `.woff2`, `.ttf`, `.otf`, `.eot`) in the web folder: the build doesn't embed it, so it is missing in the deployed app (it works only from a disk folder). Embed the font as a `data:` url in a `.css` file (see `brand/fonts.css`). The brand font sources `brand/fonts/*.ttf` are in the default skip list (not in `srcData` folders, see `file-name-dots`) |
| `element-css` | warning | Page css (`.css` files and `<style>` elements, also `app/app.css`) that restyles a bare `button`, `input`, `select` or `textarea`, a bare table element (`table`, `thead`, `tbody`, `tr`, `th`, `td`: the Sw.Table grid), `img` or `iframe` (the last two groups only in `.css` files and in pages that load the bundles: an export document may style its own table), or sets `font` / `font-size` / `zoom` on a bare `body` / `html` (a `var(--sw-*)` / `var(--Theme*)` value is fine): the rule also changes the Sw components of the page (tables, pagers, dialogs, menus, text boxes, pictures), ex: `button { width: 100% }`, `td { padding: 0 }`. A selector is page scoped when the element has a class or id (`button.QuickLink`, a page attribute such as `[data-act]`; generic attributes such as `[type=text]` don't count) or an ancestor has a class, id or attribute (`.my-page button`, `:where(.layout) button`, `body.my-page`) or is a custom element of the page (`tiu-display input`; `sw-*` / `SysWeaver-*` elements are the framework's and don't scope). The framework's own style sheets (`sw/`, `core/`, `ui/`, `shell/`, `common/`, `brand/`, `app/application.css`) are not checked. A deliberate rule is allowed with a `SwWeb:allow-element-css` comment on the selector line or the line before. HTML documents that load no bundle (an export document, a redirect page) and mail templates (`*Mail.html`) are not UI pages: neither this rule nor the design rules check their css (fragments without `<html>` / `<body>` are checked) |
| `body-overflow` | warning | Page css that sets `overflow` or `overflow-y` to `hidden` / `clip` on a bare `body` or `html`: everything below the fold is clipped, on phones also the pager and the buttons (a real porting failure: FakeText). Let the page scroll, or scroll an inner element. A full window layout that scrolls its own panes (a map, a canvas, Fake Mail) is marked with a `SwWeb:allow-element-css` comment |

#### UX guide rules

The `ux-*` rules check the rules of the [SysWeaver UX guide](https://github.com/dosh1974/SysWeaver/blob/main/_docs/UX_Guide.md) that a static check decides with few false positives; the rule id is `ux-` + the guide rule (`ux-inp-25` checks UX-INP-25) and every message ends with the guide rule and its section (`(UX guide INP-25: _docs/UX_Guide.md#1-input-pointer-touch-and-keyboard)`). They are design rules: warnings (except one: an `OnClick` that starts work and returns no promise, `ux-fbk-2`, is an **error**, and it is also checked in the framework's own files without `--framework`, so the framework's pages can't ship it either; `common/common.js`, the frozen legacy bundle, excepted), only with `--design` (so `check --strict --design`, the gate of the guide's page review checklist, covers them), page files only unless `--framework` is given, not in pages marked `SwWeb:no-framework`. The rest of the guide is checked by browser tests or a review (its `auto` / `manual` tags).

**Allow comment:** `SwWeb:allow <rule id> [<rule id> ...] (reason)` on the line or the line before, ex: `/* SwWeb:allow ux-inp-11 (a drag handle, its hover helps on touch too) */`. It names the rule: `SwWeb:allow-design` doesn't allow a UX rule, except for `ux-pop-1`, `ux-pop-9` and `ux-inp-25`, which were `design-own-ui` / `design-viewport` findings before.

**How the script rules read a script.** The usage rules judge what code does, not how it is spelled. SwWeb lexes the script and builds its call structure: the functions with their nesting (arrows, function expressions and declarations, methods), the local functions a handler calls (followed up to 4 calls deep), the callbacks it runs at once (`forEach` / `map` ..., `then` / `catch` / `finally`, an IIFE, a `Promise` executor) or later (`setTimeout`, `requestAnimationFrame`, `queueMicrotask` ...: "deferred"), and whether each request's promise is returned, awaited, kept in a returned / awaited variable, or handed to a tracker (`Sw.Dialog.Working({ Promise })`, `Sw.Activity.Track(p)`, `SetBusy(p)`). Values are followed through aliases (`const b = btn`, `const e = x.E`, `x.querySelector("tr")`), destructuring (`const { Button, Net } = Sw`, `const { confirm: ask } = window`), request aliases (`const send = Sw.Net.Send`), local wrappers of a Sw component (`const B = o => new Sw.Button(o)`, `mk(name, fn)` with `OnClick: fn`: their options and handlers are checked as such) and `Object.assign(document.createElement("input"), { ... })`. A property is one write whatever the spelling: `x.p = v`, `x["p"] = v`, `Object.assign(x, { p })`, `setAttribute("p")`, the attributes of `Sw.el`; a style also `style.setProperty`, `style.cssText`, `setAttribute("style")`, `Object.assign(x.style, ...)`. Markup in a script string (`innerHTML`, `insertAdjacentHTML`, templates) is scanned as markup. A handler given by name is reported at the `OnClick` that uses it.

**The frozen corpus** (`SwWeb.Tests/Corpus`, `expected.txt`): every page the critics planted mistakes in (series 4, rounds 1-2: sneak4, the naive pages, sneak5, r2/bc, misuse.js, misuse2.js, the lab page) and a held-out set written without seeing the checker, with the expected finding per planted mistake, the lines that must stay without one (the right patterns, findings for the wrong reason before) and the files that must be clean. `CorpusTests` asserts each one and prints the catch rate per set; add each round's new planted set (first measured unseen, then frozen), so a rule tuned to one spelling shows up. Round 2: frozen corpus 82 → 137 of 137, the Architect's unseen sneak5 8 → 30 of 30, the held-out set 15 → 24 of 32 on its first run (unseen), 32 after. Round 3 (the rule families below): the Architect's unseen sneak6 18 → 37 of 37 (0 false positives on his 5 correct pages), the FrontendDev's misuse3 / rep / sec 1 → 11 of 11 static (+4 run time only), a new held-out set H2 written by a sub-agent for the 5 families **23 of 34 on its first run** (1 false positive, a drag start), 31 of 31 static after (3 items are run time only); corpus 216 of 216. A planted item may name other places that count (`file:line;file:line`), and `tr-untranslated` counts for planted untranslated texts.

**Rule families (round 3).** The rules judge a family, not a spelling: a *secret* is any name or key whose words say so (`apiKey`, `inv.apiKey`, `refresh_token`, `SessionId`, `passphrase`, also German / Swedish / Norwegian / Spanish / French words), wherever its value goes; *raw html* is any html sink whose value has a part that is neither a literal, a translation, escaped (`esc*` / `encode*` / `sanitiz*` calls) nor the framework's own html (`Sw.*`); *formatting by hand* is a number made with `toFixed` / `Math.round` / a division by 1024 / 1000 / `* 100` next to a unit, a fixed locale, `Intl.NumberFormat` / `DateTimeFormat`, a time from `getHours()` and separators; an *action on a pointer event* is a handler that calls work (a request, a function or method of the page, navigation), not only visual feedback or a drag start (move listeners, pointer capture, recorded coordinates); a *silent failure* is a request whose rejection nobody handles.

**Rule families (round 4): generalized by family, measured by mutation.** `SwWeb.Tests/UxVariantTests.cs` generates each mistake of a family in many spellings (sinks x sources x wrappers: the handler itself, a helper, a class method, an object method, a function given by name, a `then` callback, a listener, a key handler, a timer, the page start, a loop, `forEach`; aliases and destructuring) and the right pattern in the same spellings: 1815 variants, every mistake must be found by one of the family's rules and every right variant must stay without one (`SWWEB_VARIANT_DUMP=<file>` writes the failing ones). What the families mean now:
- *the work of a user action* is every function a handler reaches (handlers of Sw options, footer buttons, listeners of user events, `Sw.OnClick`, `Sw.Keys.Add`, and every local function or method they call): a swallowed failure or an untranslated thrown text there is the user's (a developer assertion, `"Invalid format " + f`, is not);

### migrate

Rewrites a folder of old format pages (`common/common.js`, `app/application.js`, `app/application.css` and the old globals) to the new format (`sw/core.js`, `sw/ui.js`, `sw/shell.js`, `sw/ui.css`, `sw/shell.css` and the `Sw.*` API, see the porting guide [`PORTING.md`](https://github.com/dosh1974/SysWeaver/blob/main/SysWeaver.HttpServer/srcWeb/PORTING.md)). The legacy bundles keep old pages working, so migration is optional and can be done page by page; it is safe to run again at any time (idempotent).

```
SwWeb migrate D:\SysWeaver.Services\FakeTextService\srcWeb --dry-run --report migrate.md   # what would change
SwWeb migrate D:\SysWeaver.Services\FakeTextService\srcWeb --backup D:\backup\FakeText       # do it, keep the originals
SwWeb migrate D:\MyProject\srcWeb --include "app/**" --exclude "app/old*.js"
SwWeb migrate D:\MyProject\srcWeb --level includes            # only the include tags of pages that are already clean
SwWeb migrate D:\MyProject\srcWeb --map my_libraries.json     # extra mappings (ex: Table, Edit, Chat libraries)
SwWeb mapping > default_map.json                              # the embedded default mapping table
```

| Option | Meaning |
|---|---|
| `--dry-run` | Write nothing; the console output / report shows every change that would be made |
| `--backup <dir>` | Before a file is written, copy the original to `<dir>/<relative path>` (only changed files; `<dir>` may be inside the folder, it is never migrated itself) |
| `--report <file>` | Write a report: markdown if the file name ends with `.md` (summary table, changes / warnings / info per file), else text (one `path(line,col): kind: message` line per item) |
| `--include <glob>` | Only migrate matching files (repeatable; same patterns as `check --skip`: `name/`, `*.js`, `a/**/b.js`) |
| `--exclude <glob>` | Don't migrate matching files (repeatable) |
| `--level <level>` | `api` (default): include tags + legacy global renames + css hook report + design token alias renames. `includes`: only include tags (no JavaScript or css is changed, so only pages whose scripts don't use legacy globals any more are switched). `design`: `api` plus the Design v2 rewrites (invalid shadows, viewport, zoom, `sw-root`) and, as manual follow-up warnings (`check: <rule>: ...` / `design: <rule>: ...`), everything `check --strict --design` reports on the folder after the run (see "Design v2" below) |
| `--map <file>` | Extend / override the default mapping table (see below) |
| `--legacy <file>` | Another legacy globals list (names without a mapping are reported, default `legacy_globals.txt`) |
| `--keep-legacy` | The old safety gate: keep pages that still use legacy globals (after the renames) on `common.js` / `application.js` / `application.css` instead of migrating them with `sw/compat.js` |
| `--force-includes` | Switch the includes of pages that still use legacy globals WITHOUT adding `sw/compat.js` (they will break until fixed) |
| `--no-jsdoc-header` | Don't add JSDoc file headers to `.js` files without one (see "Contract fixes") |
| `--quiet` | Only print the summary |

Every item is printed as `path(line,col): change|warning|info: message`; changes are `old -> new`.

#### What is automatic

**HTML pages** (`.html` / `.htm`):

| Old include | New |
|---|---|
| `<script ... src="P/common/common.js">` | `<script ... src="P/sw/core.js">` + `<script ... src="P/sw/ui.js">` |
| `<script ... src="P/app/application.js">` | `P/sw/shell.js` when the page uses shell features (`appMain`, `App`, `AppParams`, `MainMenu`, `MainMenuStyle`: entries with `"Shell": true`), otherwise removed (pop-ups and menus are in `sw/ui.js`). The decision is reported as info |
| `<link ... href="P/app/application.css">` | `P/sw/ui.css` (+ `P/sw/shell.css` when the page uses shell features) |
| `<link ... href="P/common/theme.css">` | kept; `P/sw/ui.css` is added after it when the page used `common.js` and has no `ui.css` yet (without a theme link it is added after the scripts, with a warning) |

- `P` is whatever comes before the known suffix and is kept as is: `../`, `../../`, nothing (root), template prefixes like `${@Base Url}` (reported as info). A query / hash (`?v=2`) is kept on every new tag.
- The new tags are copies of the old tag text with only the url replaced: attribute order, quoting style (`"`, `'`, none), case (`<SCRIPT SRC=..>`), `defer` / `async` (or none) and other attributes are kept. They are written at the same position, one per line with the indentation of the old tag and the file's line ending. A removed tag alone on its line removes the line.
- Tags in HTML comments, text, non-JavaScript scripts and unrelated tags are never touched. A fully templated src (`$(COMMONJSFILE)`, `${X}`) is not analyzed (info).
- New tags that already exist are not added again (a page that has both `sw/core.js` and `common.js` loses the `common.js` tag).
- **Remaining legacy names (compat bundle)**: when the page's JavaScript (inline scripts, `on*` attributes and its local `src` scripts, after the renames of this run) still uses legacy globals, the page is switched to the new format anyway and also gets the compatibility bundle: `P/sw/compat.js` right after `sw/ui.js` and `P/sw/compat.css` after `sw/ui.css` / `sw/shell.css` (sw/compat.js = the old common.js / application.js globals on top of the already loaded core / ui, see `SysWeaver.HttpServer/srcWeb/README.md`). One warning lists the remaining names with their file / line, so a developer can rewrite them and then remove the two compat includes. Running migrate again on such a page reports as info whether `sw/compat.js` is still needed (and for which names) or can be removed; `SwWeb check --strict` reports their uses as `legacy-compat` warnings. `--keep-legacy` restores the old safety gate (the legacy includes are kept, "legacy includes kept (--keep-legacy) ... fix them and run migrate again"); `--force-includes` switches without the compat bundle. Scripts are resolved relative to the page; when the folder contains several `srcWeb` / `srcData` folders (several projects, merged into one web root by the server) a script missing in the page's own project is looked up in the others. Scripts that can't be found or are outside the folder are reported as info and don't block.
- Inline scripts and `on*` event handler attributes get the JavaScript renames below; `<style>` elements get the CSS report.
- **Page parts** (`--level api`): a new-format page (or one migrated now) whose inline scripts, handlers or own scripts (after the renames of this run, so an inline `Table.addTable` counts) use a library api gets the library's include if it is missing (check rule `missing-include`): `Sw.Table` -> `explore/table.js` after `sw/ui.js` and `explore/table.css` after `sw/ui.css`, `Sw.Shell` -> `sw/shell.js`, `Sw.Edit` -> `edit/Edit.js`, `Sw.Upload` -> `common/fileUploader.js`, `Sw.AuthUi` -> `auth/AuthUi.js`, `Sw.Chat` -> `chat/chat.js` (the prefix of the bundle tag is kept, ex: `../` or `${@Base Url}`; optional uses and shared helpers whose other pages load the library don't count). With `--level design` the body gets `class="sw-root"` (rule `design-sw-root`; not the shell, `index.html` / `debug.html`, pages with a `SwWeb:no-sw-root` comment).

**JavaScript** (`.js`, inline scripts, `on*` attributes; `--level api`): token level renames driven by the mapping table:

- Only identifier tokens are rewritten: never strings, comments, template literal text (substitutions `${...}` are code and are migrated), regex literals or HTML text.
- Only uses as a global: not member accesses (`x.Fail`, `x?.Fail`), object keys (`{ Fail: 1 }`), method names (`class A { Info() {} }`, `{ Info() {} }`, getters / setters / static), or names declared in the same code.
- Scope-light declaration analysis: `function` / `class` names, `var` / `let` / `const` declarators (with object / array destructuring, defaults, rest), function / method / arrow parameters (including patterns), `catch` bindings. Each local declaration gets a conservative scope (the enclosing block for `let` / `const` / `class` / `var`, the loop body for a `for (...)` header, the function body for parameters and named function expressions, the `catch` block for its binding). Uses of a legacy name inside the scope of a local declaration (ex: `let delay = 100; setTimeout(fn, delay);`) are the local and are neither renamed nor reported. The scopes of `let` / `const` / `class`, parameters, `catch` bindings and function expression names are exact: a use outside all of them is the legacy global and is renamed (ex: `const isMobile = ...` in one method, `isMobile()` in another). A `var` or a function declaration may be visible beyond its range (function scope, hoisting), so a use outside it is not renamed and reported as a warning (it may mean the global). A legacy name declared at the **top level** of any file or inline script of the folder is a page global: it is never renamed in any file of the folder (info at the declaration).
- Shorthand properties are expanded: `{ delay }` → `{ delay: Sw.Util.Delay }` (in a destructuring assignment they are reported).
- Reported, not rewritten: `typeof X` (Sw may not be loaded where it is tested), assignments (`X = ..`, `X += ..`, `X++`), `window.X` / `self.X` / `globalThis.X` (except a read of a plain rename, below), legacy objects used without a member, members without a mapping, entries of kind `Report` (signature differs: argument order, return type ...) with the suggested new call and a note, legacy names without any mapping (from `legacy_globals.txt`).
- A read through the global object of a plain rename of the core / ui api (no members, argument rules or library alias; not written, not after `typeof`, not a name a file of the run assigns to `window`) is rewritten: `if (!window.Narrow)` -> `if (!Sw.Layout.Narrow)`.
- Argument templates (`Args`): `waitEvent2(f, "load", "error", () => {...})` -> `Sw.Util.WaitEvent(f, ["load", "error"], undefined, () => {...})`. Arguments that keep their order stay in place (only the text between them changes); a call whose arguments change their order is replaced as a whole with the renames inside the moved arguments applied, and only when every moved argument is free of side effects (a name, a literal, a member read, a function or arrow function); otherwise it is reported.
- Options conversion (`Positional` / `Options` entries): `sendRequest(url, data, true, null, blob)` → `Sw.Net.Send(url, data, { Reload: true, ErrHandler: null, Blob: blob })`; only the arguments that were passed are converted (so omitted ones stay `undefined`), argument text (including nested renames) is kept; spread arguments or too many arguments are reported. An option named `-` drops its argument (the new API ignores it), but only a simple one (a literal, a name or a signed number; anything else could have a side effect and is reported): `Table.addTable(url, el, 20, p)` → `Sw.Table.Create({ Url: url, Element: el, Param: p })` (`Positional: 0`, rowsPerPage dropped).
- A library that publishes its own legacy alias (`window.Edit = Edit`, `if (!window.Edit) ...` in a file that assigns `window.X` for a name of a `Library` section) gets one info, not a warning per use.
- Never touched: `_T`, `_TF`, `_TH`, `_TFH` (translation functions, rule 7), `setTheme`, `resetTheme`, `toggleTheme`, `appendTheme`, `getTheme`, `applyTheme`, `Build`, `appMain` (a map entry for them is ignored with a warning). The replacement text of an entry may not contain quotes, `${` or `_T`, so a rename can never break the translation or template rules.

**CSS** (`.css` files and `<style>` elements, `--level api`): selector hooks with a `Css` mapping (`SysWeaver-Button`, `.KeyClick`, ...) are found in selector context only (not in comments, strings, declaration values or at-rule preludes; group rules like `@media` are scanned). Entries with `"Safe": true` are rewritten, all others (the default table) are reported only, because elements created by old code keep the old names. The `--Theme*` variables are never rewritten (reported by `--level design`).

**Design tokens** (`.css` files, `<style>` elements, `style` attributes and JavaScript string / template literals, `--level api`): `var(--old)` uses of the old token names that Design v2 keeps as aliases (map `Tokens` entries with `"Safe": true`, section `design`) become the new names: `--sw-bg-1` → `--sw-surface`, `--sw-bg-2` / `--sw-bg-inset` → `--sw-surface-sunken`, `--sw-bg-3` → `--sw-surface-strong`, `--sw-line` → `--sw-border`, `--sw-line-strong` → `--sw-border-strong`, `--sw-muted` → `--sw-text-2`, `--sw-faint` → `--sw-text-3`, `--sw-accent1-fg` → `--sw-text-accent`, `--sw-shadow` → `--sw-elev-1`, `--sw-backdrop` → `--sw-scrim`, `--sw-touch` → `--sw-control-h`, `--sw-size` → `--sw-text-md`, `--sw-speed` → `--sw-dur-2` (`ui/tokens.css` defines each alias as `var(--new)`, so the value is identical; `--sw-gap` is not an alias: Pro sets its own). Comments are skipped, fallbacks are kept (`var(--sw-line, #ccc)` → `var(--sw-border, #ccc)`). A token that a file of the run **defines** (an override like `--sw-touch: 52px` or `style.setProperty("--sw-touch", ...)`) is not renamed anywhere in the run: a use inside the override's scope reads the override, the new name wouldn't (the design report flags the override).

**Design v2** (`--level design`): the uses of the legacy theme variables that have one context-free role token (map `Tokens` entries with `"Apply": true`, `"TextNew"` in text colour properties: `color: var(--ThemeAcc1)` -> `var(--sw-text-accent)`, `background: var(--ThemeAcc1)` -> `var(--sw-accent1)`, `var(--ThemeAcc2)` -> `var(--sw-accent2)`, `--ThemeRad` -> `--sw-radius-md`, `--ThemeFadeDuration` -> `--sw-dur-2` ...) are renamed in css, style attributes and script strings (a variable that a file of the run sets below the root blocks its renames; a root theme such as `:root { --ThemeAcc2: ... }` does not; a fallback of a role token is left alone); the role dependent ones (`--ThemeMain`, `--ThemeBackground`, the derived mixes) stay `design-legacy-token` warnings. The invalid shadow `<lengths> var(--sw-shadow)` / `var(--sw-elev-N)` (the browser already ignores it) becomes `none` (`!important` kept; the note says a floating layer gets `var(--sw-elev-1)` by hand), a missing viewport tag is added, a zoom blocking viewport loses `user-scalable=no` / `maximum-scale=1`, and UI pages get `class="sw-root"` on the body. Then **`check --strict --design` runs on the folder as it is after the run** (in a dry run the migrated texts are checked in memory) and every finding becomes a warning `check: <rule>: <message>` (contract and porting rules: `element-css`, `body-overflow`, `missing-include`, `script-order`, `legacy-*` ...) or `design: <rule>: <message>` at its line, mapped back to the line of the file before the run; a legacy name that migrate already reports on that line is not listed twice. The markdown report starts with the manual follow-ups by rule. A dry run with `--level design --report port.md` is therefore the complete porting worksheet of an app: the changes are the automatic part, the warnings are exactly what `check --strict --design` will report after the migration.

**Never migrated**: the default `check` skip list (`external/`, `prettier/`, `ace/`, `node_modules/`, hidden folders, `bin/`, `obj/`, `*.min.js`, `marked.js`, `md5.js`, `UZIP.js`, `chart.umd.js`, `chartjs-*.js`), the new library folders `core/`, `ui/`, `shell/`, `sw/` (any folder with that name), the legacy bundles / theme source / legacy compat css `common/common.js`, `app/application.js`, `app/application.css`, `common/theme.css`, `common/common.css`, every file whose header contains `GENERATED by SwWeb`, and files that aren't valid UTF-8 (warning).

**Contract fixes** (`--level api`): a `.js` file without a JSDoc file header gets one (`/** @file <path> - (added by SwWeb migrate: describe ...) */`, check rule `jsdoc-header`; `--no-jsdoc-header` disables it). Newline escapes (`\n`, `\r\n`, `\r`) in the literal of a `_T` / `_TH` / `_TF` / `_TFH` call (check rule `tr-newline`: the minifier makes them backtick literals that the server doesn't translate) become format placeholders whose argument is `String.fromCharCode(10)` (not a quoted literal, which would be taken as the translation context), inserted after the format arguments: `_T("Failed.\n{0}", e, "ctx")` -> `_T("Failed.{1}{0}", e, String.fromCharCode(10), "ctx")`. `_TF` / `_TFH` become `_T` / `_TH` (only when the text has no `{`). Line continuations, missing format arguments and spreads are reported.

**Framework-free pages** (`--level design`, rule `no-framework`): a UI page without any SysWeaver bundle gets `common/theme.css`, `sw/ui.css`, `sw/core.js`, `sw/ui.js` (relative to the page, deferred) before its own first style sheet / style / script, the viewport tag (after the charset meta tag) and `class="sw-root"`, all in one run (a second run changes nothing, so the dry run is exact); its port steps (own fetch, dialogs, palette, icons, frames of pages of this site, also when code sets the frame's src, no `_T` when its scripts make texts ...) are warnings at their lines in the page and its own files; after the includes the steps that remain are check rules (`tr-untranslated`, `design-font`, `design-own-ui`, `design-page-header`), so the worksheet of a later run still lists them. The summary counts the framework-free pages (any level). A page with a `SwWeb:no-framework` comment is left alone.

**More automatic changes** (`--level design` unless noted):

- `common/theme.css` before `sw/ui.css` in a page that links `sw/ui.css` without it (`api`; also when old includes are rewritten and the page had no theme link) - rule `theme-include`.
- `_T(...)` around a plain literal text in a script of pages on the framework (the places of `tr-untranslated`; not a literal with `{`, escapes or both quote kinds, html, a concatenation, a template, a line marked `SwWeb:no-tr`): `Sw.Toast("Saved")` -> `Sw.Toast(_T("Saved"))` (add the context by hand). Scripts that a page without the framework also loads are left alone.
- A CDN script of a library the framework serves: Chart.js (`cdn.jsdelivr.net/npm/chart.js`, unpkg, cdnjs), `chartjs-plugin-datalabels`, `hammerjs` -> `chart/external/...` (SysWeaver.MicroService.ChartJs) - rule `external-resource`.
- `Open(url)` -> `Sw.Page.Navigate(url, "_blank")` (`api`; the old default was a new tab, Navigate's is the same tab).
- `var(--ThemeMain)` in a text colour property (`color`, `fill` ...) -> `var(--sw-text)` (map entry `TextNew` without `Apply`: renamed only in text colour properties).

**Files**: only changed files are written, with their original encoding (UTF-8, BOM kept or not) and line endings (only the changed ranges are replaced; inserted lines use the file's line ending).

#### Mapping file

The default table is [`migrate_map.json`](migrate_map.json) (embedded; print it with `SwWeb mapping`), built from the old globals and their `Sw` counterparts (PORTING.md part A). It has one section per library: `core`, `ui`, `shell` (the old common.js / application.js names) and the feature library legacy aliases `table`, `edit`, `chart`, `chat`, `auth`, `usermanager`, `passkey`, `upload`, `media`, `tags`, `anim` (sections with `"Library": "<file>"`: only pure renames - the old name is the same object / function as the new one - are rewritten, wrappers with other arguments or results are reported; their reported uses keep working through the library and don't make a page need `sw/compat.js`). More sections can be added by a `--map` file in the same format, which is merged over the default: new sections are added, entries with the same name replace the default ones, `"Replace": true` at the root drops the default first. Comments and trailing commas are allowed.

```jsonc
{
  "Sections": {
    "mylib": {
      "Description": "my/lib.js",
      "Library": "my/lib.js",                                    // optional: the names are aliases my/lib.js still provides
      "Globals": {
        "delay": "Sw.Util.Delay",                                  // rename every global use
        "isMobile": { "Kind": "Property", "New": "Sw.Platform.IsMobileDevice" }, // isMobile() -> property
        "getRequest": { "New": "Sw.Net.Get", "Positional": 1, "Options": [ "Reload", "Blob", "Setup", "Read" ] },
        "Confirm": { "New": "Sw.Dialog.Confirm", "MaxArgs": 3 },   // only calls with <= 3 arguments
        "waitEvent": { "Kind": "Report", "Suggest": "Sw.Util.WaitEvent(target, name, timeout, fn)", "Note": "argument order differs" },
        "MyTable": { "Members": { "add": "Sw.MyTable.Add", "old": { "Kind": "Report" } }, "New": "Sw.MyTable" },
        "App": { "New": "Sw.Shell.App", "Shell": true },           // a shell feature (page gets sw/shell.js)
        "MyHelper": { "Kind": "Ignore" }                           // not legacy (no rewrite, no report)
      },
      "Css": {
        "SysWeaver-Table": { "New": ".sw-table" },                 // element hook, report only
        ".TableRow": { "New": ".sw-table-row", "Safe": true, "Note": "renamed by the table rewrite" }
      },
      "Tokens": {
        "--mylib-line": { "New": "--sw-border", "Safe": true },    // an alias: var(--mylib-line) -> var(--sw-border)
        "--MyLibRad": { "New": "--sw-radius-md", "Note": "only defined where my/lib.css is loaded" } // reported (design rules)
      }
    }
  }
}
```

| Entry member | Meaning |
|---|---|
| (string) | Same as `{ "New": "..." }` |
| `Kind` | `Rename` (default when `New` is set), `Property`, `Report` (default without `New` / `Members`), `Ignore` |
| `New` | The replacement expression (ex: `Sw.Util.Delay`) |
| `MaxArgs` | Rename only calls with at most this many arguments, report other uses |
| `Positional`, `Options` | Keep `Positional` arguments, turn the following ones into `{ Option: arg, ... }`; more arguments than options are reported; an option named `-` drops its (simple) argument |
| `Suggest`, `Note` | Shown in warnings (and the note also with changes) |
| `Shell` | The name is a shell feature (`application.js` → `sw/shell.js` instead of removed) |
| `Args` | The new argument list: `"$0, [$1, $2], $4, $3"` (waitEvent2 -> Sw.Util.WaitEvent). `$n` is the n:th old argument, each at most once; a trailing reference to an argument that wasn't passed is left out with its comma, an inner one becomes `undefined`; old arguments that aren't used must be simple values (dropped). Not with `Options` / `MaxArgs`; no quotes, `${` or translation function names |
| `Members` | A legacy object: `Old.member` is mapped per member (member entries have the same form, without `Members`); unmapped members use `New + ".member"` when `New` is set, else are reported; a bare `Old` uses `New` or is reported |

`Css` entries: key `.Class`, `#id` or an element name, value a string (the new selector) or `{ "New", "Safe", "Note", "OwnUi" }` (`OwnUi`: the core still draws the old element on pages without `sw/ui.css`, ex: `SysWeaver-ServerBlock`; `upgrade` reports a page's rule for it as info).

`Tokens` entries: key a custom property (`--name`), value a string (the suggestion, reported) or `{ "New", "Safe", "Note" }`; a `Safe` entry needs a custom property as `New` and must be a real alias (the old token is defined as `var(--new)` wherever it exists), its `var()` uses are renamed. The default `design` section holds the Design v2 aliases (safe) and the legacy `--Theme*` / `--SysWeaverEdit*` variables (reported with the role token to use).

Section members: `Description`, `Globals`, `Css`, `Tokens`, and `Library` (the file that still provides the section's names as legacy aliases: their warnings say so, and they never make a page need `sw/compat.js`).

#### Exit code and follow-up

`0`: no warnings (whether files changed or not). `3`: warnings that need manual follow-up (remaining legacy globals, kept includes, reported css hooks ...). `2`: invalid command line (unknown option, invalid `--level`, missing folder / map / legacy file, `--backup` equal to the folder). `1`: an error (ex: invalid json in the map). Fix the warnings by hand (the report gives file, line, old use and the suggested new call), then run `migrate` again: pages kept with `--keep-legacy` are switched once they are clean, pages on `sw/compat.js` get an info when the compat includes can be removed. Then run `SwWeb check <folder> --strict` (`legacy-compat` warnings list what still needs `sw/compat.js`).

### upgrade

```
SwWeb upgrade D:\Hypnos --dry-run --report upgrade.md     # what would change (a folder above the web roots: every srcWeb / srcData below it)
SwWeb upgrade D:\Hypnos --backup D:\backup\Hypnos          # do it
```

Moves an app from the old `common/common.js` / `app/application.js` to the new scripts with the least change, so it works as before on the new framework and the legacy bundles can go. It is `migrate --level api` (the include tags, the legacy global renames, argument conversions, the token alias renames, the library includes) with these differences:

- **A page with its own UI keeps its look.** A page that linked no SysWeaver style sheet (no `common/theme.css`, `app/application.css`, `sw/ui.css`, `sw/shell.css`) draws its own UI: it gets `sw/core.js` + `sw/ui.js` in place of `common/common.js` and no style sheet (no `common/theme.css`, `sw/ui.css`, `sw/compat.css`, which would restyle it; the old common.js added none). An info says so. On such a page the core draws the server block overlay itself, as the original's elements when the page styles `SysWeaver-ServerBlock` (core/README.md `FallbackBlock`), and a chart it frames with its own theme (`usetheme=name@css`) keeps the server's colors and design (chart/README.md). Pages that linked the SysWeaver theme get `sw/ui.css` as with `migrate`.
- Nothing that isn't needed to run on the new scripts: no JSDoc file headers, no translation literal fixes (`tr-newline`), no Design v2 rewrites (`--level design` is refused: that is `migrate --level design`, the later port).
- Pages that never used the framework (`no-framework`) and css hooks the core still draws on such pages (`OwnUi` map entries, ex: `SysWeaver-ServerBlock`) are info, not warnings.

What remains are the legacy names that have no automatic rewrite: the page then gets `sw/compat.js` (+ `sw/compat.css` when it links the SysWeaver theme) and a warning lists them (ex: the old `Button` class, whose instances have another api); rewrite them and run `upgrade` again. The exit codes are those of `migrate`.

### verify-build

```
SwWeb verify-build D:\SysWeaver            # after a build: every web/**/*.br, data/**/*.br (and *.gz) the projects embed
```

`check` reads the sources; the browser tests of the scratch apps serve srcWeb from disk too. What ships is the output of the build's minifiers (`Compress.exe` -> `minify.exe`, `shader_minifier.exe`), and they have broken correct sources: the chart.js "Cannot access 'o' before initialization" (only in the built file, line 11, column 137211), two image effects with duplicate functions, an empty `TwinklingTunnel.glsl`. `verify-build` decompresses every built `.js` / `.mjs` / `.css` / `.html` / `.htm` / `.glsl` output below the folder (not `bin/`, `obj/`, `srcWeb/`, `srcData/`, hidden folders) and reports, as errors (exit code 3):

| Rule | What |
|---|---|
| `build-read` | The output can't be decompressed |
| `build-empty` | The output is empty while its source isn't (the source: the same path below `src` + the output folder's name, ex: `web/x.js.br` <- `srcWeb/x.js`; a source with only comments / a BOM may minify to nothing) |
| `build-js-syntax` | A minified script (also a script element of a `.html` output) has an unterminated token or unbalanced brackets |
| `build-js-tdz` | Minified code reads a name before the declarator of the same `const` / `let` declaration that declares it (its initializer, a destructuring default or computed key), or, for `var`, a destructuring default / computed key that reads a later declarator: the shape the `minifier-reorder` bug produces (`const{end:o=s-1}=i,s=t.length`). Reads inside a nested function, arrow, method or class body are not counted (they run later), except a function called at once; a `var` declared again is not reported |
| `build-glsl-duplicate` | A shader defines two functions with the same name and parameter types (in the same preprocessor branch): it doesn't compile (shader_minifier renamed an overload, see Compress `--no-overloading`) |
| `build-glsl-brackets` | A shader has unbalanced brackets |

The parity gate's `release-js` / `release-glsl` scenarios (SysWeaver.Tests `ParityTests/Plugins/ReleaseAssetsPlugin.cs`) parse every built script with the browser's own parser and compile and link every built shader with the built `media_effect_program.js` in WebGL. `SwWeb.Tests` runs `verify-build` on the sibling SysWeaver repository (`BuildVerifierTests.TheSysWeaverBuildOutputsVerify`, as of its last build).

## Limitations and considerations

- The regex / division decision is heuristic (as in every JavaScript tokenizer without a parser); rare constructs such as `x = function(){} / 2` lex as a regex. All SysWeaver and vendored sources lex correctly.
- `legacy-global` is token based: a local variable or parameter that shadows a legacy name (not declared with `var`/`let`/`const`/`function`/`class` in the same script) is reported.
- The HTML scanner doesn't build a tree or decode character references; attribute values are raw.
- `external-resource` and `external-request` only see urls written in the file (tags, CSS, `import`, literal arguments of the request functions); internet urls built at run time from variables (`Sw.Net.IncludeJs(base + x)`, map tiles) need a review.
- `element-css` and `body-overflow` read selectors, not the DOM: styles set from JavaScript and component css injected at run time are not seen.
- The design rules are heuristics for porting, not proofs: `design-shadow` can't tell a floating layer (which may keep `var(--sw-elev-1)`) from a permanent surface, `design-page-header` only sees the page's own scripts inside the checked folder (a library outside it that makes the header, or a header built from data, is not seen: mark the page), `a11y-custom-control` only sees HTML `onclick` and `el(...)` props (not `addEventListener`), and colours built at run time are not seen. Mark deliberate exceptions with `SwWeb:allow-design` / `SwWeb:no-page-header`.
- `tr-untranslated` sees literals in the known text places only: texts in arrays, variables or own helper functions (`addRow(name, "Total")`) are seen only by the page level "never calls `_T`" finding, which a single `_T` call silences. `design-own-ui` can't tell an own api wrapper from a fetch Sw.Net can't make when it sets none of the special request options (mark it with `SwWeb:allow-design (why)`).
- `check` doesn't know config `Variables` keys, pass them with `--template-var`.
- `migrate` has no real scope analysis: a legacy name declared anywhere in a file blocks its renames in the whole file (reported), and page globals are detected per run (migrate the whole web root, or all projects, so globals declared in other folders are known).
- `migrate` doesn't follow scripts loaded at run time (`includeJs`, `Sw.Net.IncludeJs`) when deciding whether a page is clean.
- `migrate` renames by name: a legacy global reached in another way (`window["Fail"]`, `const w = window; w.Fail()`, `eval`) is not found. `window.X` is reported, not rewritten.
- `migrate`: class fields named like a legacy global (`class A { Fail = 1 }`) are reported as assignments (`check` ignores them).
- The default CSS mappings are report only. Library alias renames need the library's script on the page (it already defines the old name). Generic library names (`Edit`, `Table`, `Chat`, `MathTools` ...) are renamed only where they aren't declared in the migrated code (a local or page global with the same name blocks the renames, reported as info).
